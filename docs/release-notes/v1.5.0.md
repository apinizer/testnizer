# v1.5.0 — the security release

Testnizer now does the certificate, key, token and signature work that used to
send you to `keytool`, `openssl`, jwt.io and a pile of one-off scripts. All of
it runs offline, inside the app, on your machine.

Everything here is **additive**. Pasting a PEM, picking a CRT/KEY/PFX file and
typing a shared secret keep working exactly as before, and remain the default on
every screen. Nothing forces you to load a keystore.

---

## New — the Security page

A dedicated page (sidebar → **Security**) collects every key, PKI, token and
identity tool:

### Keystore Studio
Open, create, edit, convert and export **JKS / PKCS#12** keystores and X.509
certificates — no `keytool`, no `openssl`. Generate key pairs and secret keys,
import in five formats, rename/delete aliases, change store and entry passwords,
and export entries as PEM/DER/PKCS#12. Keystores you save are checked for
key↔certificate match cryptographically, not by name.

### Key material from a keystore, anywhere it is needed
A certificate or private key can now come from a saved keystore instead of a
pasted PEM or a file:

- **Project Settings → Certificates → Client Certificate** (mTLS)
- **SOAP request → WS-Security → Sign**
- **Tools → WS-Security → Sign**
- the JWK, JOSE and SAML tools

The app core resolves it at execution time; the key itself never reaches the
window you are looking at.

### JWK / JWKS
PEM ⇄ JWK in both directions, key-pair generation, RFC 7638 thumbprints as
`kid`, JWK-Set assembly and validation — and **serving a JWKS** from a mock
server at `/.well-known/jwks.json`, so a service under test can fetch your keys.
Only public keys are ever published.

### JWT / JOSE — the full lifecycle
The JWT Debugger now signs as well as decodes: **HS/RS/PS/ES** signing and
verification, **JWE** encrypt/decrypt, claim editing with readable expiry, and
verification against a JWKS. Signing with a keystore-backed key happens in the
app core, so the private key never enters the editor.

### TLS Inspector
Point it at a live endpoint and see the certificate chain, expiry, protocol
versions and negotiated ciphers.

### SAML
Build an AuthnRequest / Assertion / Response, sign it (enveloped XML-DSig), and
**validate** one — with HTTP-Redirect and HTTP-POST binding encode/decode.

The validator is the point. A signature that merely "checks out" proves only
that *something* was signed, which is how XML Signature Wrapping works. This one
also proves **which element** was signed: exactly one signature, exactly one
reference, a same-document `#ID` that resolves to exactly one element, that
element being the signature's own container and either the document root or the
Response's active assertion. It refuses HMAC algorithms (which would turn your
trusted certificate into a shared secret), SHA-1 signatures and digests,
DOCTYPE/DTD input (XXE), unsigned assertions smuggled beside a signed one, and
an expired bearer-confirmation window. Every rejection names the check that
failed, so you see *why*, not just "invalid".

### Also on the page
OTP Authenticator (TOTP/HOTP), Password Generator, QR tool.

## New — sign JWS / JWT inside scripts

Pre-request and Tests scripts can mint and verify tokens, so a token can be
signed in a pre-request script, stored in a variable and sent by a later
request:

```js
const token = await pm.jose.sign(
  { iss: 'testnizer', txn: '12345' },
  pm.environment.get('signingKeyPem'),
  { alg: 'RS256', header: { kid: 'key-1' }, expiresIn: '5m' },
)
pm.environment.set('mkkJwt', token)
// …then use  Authorization: Bearer {{mkkJwt}}
```

`pm.jose.sign / verify / decode`, `signJws / verifyJws` for raw payloads, and
`generateKeyPair(alg)`. The full library is available as `require('jose')`.
**Send** and the **Collection Runner / Test Suites / Scheduled runs** get this at
the same time, producing the same bytes.

## New — run-level Setup / Teardown, with teardown that always runs

Every request in the Run Sequence now carries a **phase**: *Flow* (default),
*Setup* or *Teardown*, plus run-level **setup** and **teardown scripts**. A run
executes Setup → Flow → Teardown whatever order the list is in, and
setup/teardown run once per RUN, not once per iteration.

**Teardown is guaranteed.** It still runs when the flow stops early — stop on
error, a network failure, or you pressing Stop. Pressing Stop *while teardown
itself is running* abandons the rest of the cleanup, so an unresponsive cleanup
request can't hold the app hostage; impatient clicking during the flow never
costs you cleanup.

**Teardown never rewrites the verdict.** Its results get their own section in
the results view and the HTML report, tallied separately — a failing cleanup
does not turn a green run red, and a passing one does not hide the failure that
stopped the run. Test counts follow the same rule.

Scheduled tasks keep the phases they were created with; tasks saved before this
release run everything as flow, exactly as they did.

## ⚠️ Behaviour change — the Collection Runner now sends your client certificate

Until now, project **client certificates (mTLS) were attached only on Send**.
The Runner, Test Suites and Scheduled runs never attached one, so a request that
worked with the Send button could fail — or go out unauthenticated — the moment
you ran it from a collection. Run now uses the exact same certificate logic as
Send.

- Collections that failed against mutual-TLS APIs should now work unchanged.
- **A run that previously went out with no certificate may now present one.**
  Certificates are still matched to the request host, so one scoped to
  `api.example.com` is never presented elsewhere. But a certificate whose host
  is `*` matches **every** host a collection touches — including third-party
  APIs that previously received nothing.

> **Please check before your next run:** open **Project Settings → Certificates**
> and give every *Client Certificate* entry a specific host (not `*`). A wildcard
> is fine for CA/trust entries; for client certificates it means your identity is
> presented to every host in the run.

Failures are loud: a matching certificate that can't be loaded fails that single
request with a clear message instead of quietly going out unauthenticated.
`pm.sendRequest(...)` still attaches no project certificate, on either path.

## Fixes

- **Add Request → HTTP** opens the HTTP editor instead of leaving you on the
  protocol picker. (It looked HTTP-specific because the editor decided what to
  show from the tab's *name*; it now decides from what the tab points at, which
  also closes the same latent bug on the Tests panel.)
- **Add Folder** asks for a name instead of immediately creating "New Folder";
  Escape or an empty name creates nothing.
- The folder **collapse chevron works while the APIs search box has text** — and
  so do Collapse all / Expand all. Your real expand state is untouched by
  filtering and comes back when you clear the box.
- **Context menus no longer get cut off** at the window edge: they flip up, slide
  in and scroll internally, so Delete is always reachable — in the APIs tree, the
  Tests panel and the tab bar.
- **Running a second folder** shows *that* folder's Start-run screen instead of
  the previous run's results. A Run aimed at a folder whose run is still
  executing now focuses it rather than throwing the live progress away.
- **Export filenames keep Turkish (and any Unicode) characters** —
  `sağlık_bakanlığı` stays itself instead of becoming `sa_l_k_bakanl___`. Only
  characters the filesystem actually rejects are replaced, everywhere a filename
  is suggested (including keystore entry exports).
- **A new test suite lands where the name input said it would.**
- **Test suites: manual folder management** — create, nest, rename, delete
  folders and add requests into them.
- **AI Chat:** message text is selectable and copyable, and the view no longer
  snaps back to the bottom while a response is streaming — it stays where you
  put it until you scroll back down. (The same fix cured an app-wide problem
  where a drag released outside the window left *all* text unselectable.)
- Passwords typed into the key picker are session-only and never written to
  disk; the certificate passphrase field is write-only; trying the keystore
  option can no longer overwrite a certificate's PFX passphrase.

## Fixed after the tester round

Everything below came out of the pre-release QA pass. Where a report turned out
to have a different cause than it looked like, the cause is what got fixed.

### Collection Runner

- **"Stop run if an error occurs" now actually stops the run.** The setting was
  never reaching the runner — the checkbox value was simply left out of the call.
  Adding a flag to a run is now a compile error until every screen supplies it,
  so the class cannot come back. The same omission had been silently ignoring
  **"Persist responses"**, so switching body persistence off works too.
- **A failed Setup step skips the flow** and says so, whether or not the stop
  setting is on — if the fixture that creates the record failed, the assertions
  after it are measuring the wrong world. Teardown still runs.
- **Steps that never ran are reported** instead of vanishing: cancel a 12-step
  run after 3 and you now see 12 rows, 9 of them marked *NOT RUN*, with a real
  Skipped count. (They are counted as neither passed nor failed — previously
  such rows would have been scored as *passed*.)
- **A cleanup failure no longer inflates the Errors counter.** Teardown is
  reported on its own line and cannot move the run's verdict, which is what the
  UI has always promised.
- **Run-level script rows** show a *SCRIPT* chip instead of a meaningless green
  200, and a script that threw reads as *Error*.
- **The Console log tab works**: `console.log/warn/error` from your scripts is
  captured with levels, counted, filterable and shown per step.
- **Runs show up in the Console panel.** Traffic from a folder or suite run was
  invisible there — only hand-sent requests appeared — so the one place you
  could not debug with `console.log` was a run. Every step now logs its request
  and response, transport failures included, tagged with the run, step, phase
  and iteration it came from, and script output goes to the same place. This
  covers scheduled runs, which have no tab and are identified by their task.
- **Scheduled tasks carry the same settings** as the run they were created from,
  and editing a schedule no longer silently drops its Setup/Teardown steps and
  hook scripts.
- **"Open collection runner" opens the real runner.** The command palette used
  to open an older dialog with no Setup/Teardown, no hook scripts and no
  iteration data — a run started there quietly lost the entire run lifecycle.
  It now opens the runner tab, on the run configuration.
- **Iterations and Delay can be cleared and retyped.** Same fault as the
  password length box: the value was clamped on every keystroke, so the field
  could never be emptied and a typed digit landed beside the old one. On the
  older dialog an emptied box sent `NaN` iterations into the run.

### Security tools

- **A verdict never outlives its input.** Change the XML and SAML's green
  *Valid* disappears; paste a different token and the JWT panel stops saying
  *Signature verified*; inspect another host and the TLS chain and *Trusted*
  badge go with it. This was reported once (a PEM left over from a previous key)
  and turned out to exist in six tools.
- **TLS Inspector no longer invents findings.** A DNS failure showed *Hostname
  mismatch*, *Expired* and "expires in 0 days" for a certificate the server
  never sent. Genuine problems — untrusted, expired, wrong hostname — are still
  reported exactly as before. When the SNI differs from the host, the screen now
  says which name the certificate was checked against.
- **"Create keystore & add" works**, and a failure is shown in the dialog
  instead of turning up later as a stray error banner in Keystore Studio.
- **Keystore Studio tells you what happened**: creating, opening, saving to the
  library, changing a store or entry password, and converting all confirm. A
  wrong password appears *in* the dialog rather than behind it.
- **Converting to JKS names the entries it cannot carry** and asks first, rather
  than quietly dropping the alias count from 4 to 3.
- **A PKCS#12 store can be created without a password** (the field said
  "optional" and now means it), verified against real `openssl`. JKS still
  requires one — with an empty password its key protector derives its keystream
  from a salt stored in the file, so nothing would actually be encrypted. Adding
  a key to a passwordless store asks for an entry password.
- **Password Generator**: the Length and How-many boxes can be cleared and
  retyped, Copy confirms visibly, "Exclude look-alikes" no longer appears to
  move, turning Symbols off no longer breaks Generate, the strength readout
  responds to "no repeated characters", and the appended digit goes at the end
  (with a Random option if you prefer it).
- **JWKS "Load" reports its own outcome** next to the button. A failed fetch used
  to show up as *Invalid* beside Verify, which read as a verdict on your token.
- **JWK "Validate" says whether the JWK is valid.** It always ran; it just had
  nothing to show for it.
- **WS-Security names its one dangerous option.** Choosing **RSA-1.5** key
  transport now says what it is: the Bleichenbacher padding-oracle target,
  banned by XML Encryption 1.1. It stays selectable — talking to a service that
  only speaks it is the reason this tool exists — but it no longer looks like
  an equal choice beside RSA-OAEP. (Reported as "invalid combinations are not
  validated"; every algorithm pairing the dropdowns offer does in fact work, so
  none was taken away.)

### Elsewhere

- **Settings only close when they saved.** A failed write — including turning
  SSL verification off — used to close the dialog exactly like a successful one.
  Project settings no longer report "saved" when part of the save failed, and
  unreadable settings are reported instead of being shown as defaults that Save
  would then write over the real configuration.
- **A step that didn't run is never reported as a clean run.** Saving project
  settings, creating a project with an import or a git remote — these report
  failure the way the app actually signals it, so an import that never happened
  no longer reaches the success screen unremarked.
- **Folder authentication can't be lost**: if the stored config can't be read it
  is reported and saving is blocked, instead of quietly falling back to
  "inherit" and overwriting it.
- **Nothing you typed is discarded to make room for a sample** — the JSON↔XML and
  YAML↔JSON direction switches keep your text.
- Deleting an authenticator entry asks first (the button was labelled "Clear"),
  the HMAC secret field is masked, and copy buttons say what they copy — which
  matters most for the one that copies a **private** JWK.

## Known limitation

A keystore whose store password is **empty** still can't be remembered by the
key picker, so it can't be used as a key source without re-entering the password
each time. Creating and using such a store in Keystore Studio works (see above);
this limitation is only about the "remember password" path.
